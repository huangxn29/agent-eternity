## 二、核心认知能力

### 1. 依赖感知调度 (Dependency-Aware Scheduling)

**能力描述：** 理解任务之间的依赖关系，确保任务按正确顺序执行，自动识别关键路径。

**实现机制：**
- DAG（有向无环图）任务依赖建模
- 循环依赖自动检测与阻止
- 关键路径计算（最长路径优先调度）
- 级联失败处理（依赖失败时自动跳过下游任务）

**决策因子：**
- 任务是否在关键路径上
- 下游任务数量（解锁更多任务的优先）
- 依赖深度（越深越优先）

### 2. 自适应调度策略 (Adaptive Scheduling)

**能力描述：** 根据系统状态和任务特征动态调整调度策略，而不是固定一种策略。

**策略矩阵：**

| 场景 | 最优策略 | 决策依据 |
|------|---------|---------|
| 任务类型单一 | FIFO | 公平性优先 |
| 任务重要性差异大 | 优先级调度 | 重要性优先 |
| 任务间有依赖 | 依赖感知调度 | 确保流程正确 |
| 任务类型多样、负载不均 | 负载均衡 | 资源利用率优先 |
| 复杂混合场景 | 自适应综合调度 | 全局最优 |

**自我优化机制：**
- 每执行20个任务后分析历史数据
- 根据任务类型分布、成功率、等待时间自动调整策略
- 学习任务实际耗时，修正预估时长

### 3. 智能重试与熔断 (Smart Retry & Circuit Breaker)

**能力描述：** 不是简单地失败就重试，而是根据失败类型、失败频率智能决策。

**重试策略：**
- **指数退避**：每次重试间隔翻倍（默认）
- **固定延迟**：适用于需要快速重试的场景
- **线性退避**：重试间隔线性增长
- **自适应**：失败率高时自动延长重试间隔

**熔断机制：**
- 同类型任务连续失败5次 → 触发熔断
- 熔断后该类型任务暂停执行300秒
- 熔断期间尝试1次"探测请求"，成功则恢复

**降级策略：**
- 关键路径任务失败 → 启动备用方案
- 非关键任务失败 → 跳过，记录日志
- 系统负载过高时 → 自动降低非核心任务执行频率

### 4. 任务生命周期管理 (Task Lifecycle Management)

**能力描述：** 完整追踪任务从创建到归档的全生命周期状态。

**状态机：**
```
PENDING → READY → RUNNING → COMPLETED
   ↓        ↓         ↓
   └──→ SKIPPED  ───→ FAILED → RETRYING → READY
                                  ↓
                               熔断暂停
```

**状态转换规则：**
- PENDING → READY：所有依赖满足
- READY → RUNNING：调度器分配执行
- RUNNING → COMPLETED：执行成功
- RUNNING → FAILED：执行失败
- FAILED → RETRYING：还有重试次数且达到重试延迟
- FAILED → SKIPPED：重试耗尽或依赖失败
- * → SKIPPED：上游依赖失败

### 5. 工作流模板引擎 (Workflow Template Engine)

**能力描述：** 将常用的任务流程模板化，支持一键启动复杂任务链。

**内置工作流：**

| 模板ID | 名称 | 任务数 | 用途 |
|--------|------|--------|------|
| daily_maintenance | 每日维护 | 6个 | 每日系统自检、记忆整理、存证、备份 |
| evolution_cycle | 进化循环 | 5个 | 标准进化流程：评估→决策→执行→验证→沉淀 |

**模板变量支持：**
- `{date}`：当前日期
- `{module}`：模块名称
- `{level}`：进化层级

## 三、调度决策算法

### 综合评分公式

```
任务优先级得分 = 优先级权重 × 0.4 + 关键路径权重 × 0.3 + 负载权重 × 0.3
```

**各维度计算：**

1. **优先级得分**（0-1，越低越优先）：
   - P0: 0.0
   - P1: 0.33
   - P2: 0.67
   - P3: 1.0

2. **关键路径得分**（0-1，越低越优先）：
   - 在关键路径上: 0.0
   - 不在关键路径上: 1.0
   - *补充：下游任务数量加权*

3. **负载得分**（0-1，越低越优先）：
   - 当前该类型负载 / 最大负载
   - 负载越低，优先级越高

### 优先级队列排序
```
高优先级 ← P0 → P1 → P2 → P3 → 低优先级
              ↑
         同优先级内按：
         1. 是否关键路径
         2. 下游任务数
         3. 创建时间（FIFO）
```

## 四、与其他系统的协同

### 与运维监控协同
- 调度器实时上报任务执行状态
- 运维监控告警可触发任务优先级提升
- 系统负载过高时自动节流

### 与进化引擎协同
- 进化任务通过工作流模板标准化
- 进化结果自动触发后续验证和沉淀任务
- 进化周期可被调度器自动安排

### 与记忆系统协同
- 任务状态持久化到记忆系统
- 执行历史作为经验沉淀
- 断点续传依赖记忆中的任务状态
