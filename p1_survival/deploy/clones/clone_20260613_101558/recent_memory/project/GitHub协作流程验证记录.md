# GitHub协作流程验证记录
## 验证时间
2026-05-16

## 验证目标
验证基于GitHub Issue的智能体协作工作流是否通畅：创建→唤醒→认领→执行→评论→关闭

## 验证步骤
1. 创建3个GitHub Issue：
   - #4 分配给镇元（role:sentry）：系统巡检报告
   - #5 分配给砺元（role:breaker）：安全自检
   - #6 分配给筑元（role:constructor）：编写容器运行文档
2. 依次唤醒三个分身
3. 检查分身是否完成Issue处理

## 验证结果
✅ 全链路闭环成功：

| 分身 | Issue | 工具调用 | 评论 | 标签 | 结果 |
|------|-------|---------|------|------|------|
| 镇元🔮 | #4 巡检 | ✅ | ✅ 巡检结果评论 | ✅ done | 磁盘43%/内存3.4G |
| 砺元🔨 | #5 安全 | ✅ | ✅ 4条评论 | ✅ done | 端口/进程/权限全查 |
| 筑元⚒️ | #6 文档 | ✅ 3次exec | ✅ 2条评论 | ✅ done | 提交容器状态文档 |

## 过程中的关键问题
- 模型切换问题：clawrouter/free随机路由到不支持工具调用的模型
- 解决：改用free/gpt-oss-120b（确认支持工具），后优化为free+7模型白名单
- deepseek系列模型网络异常，nemotron系列部分不可用
- 唤醒脚本git pull卡住导致超时

## 关键结论
- GitHub协作工作流全链路可行（创建→唤醒→认领→执行→评论→关闭）
- 模型选择至关重要：必须使用支持工具调用的模型
- 7个确认工具调用可用的免费模型：gpt-oss-120b/qwen3-coder-480b/glm-4.7/llama-4-maverick/devstral-2-123b/gpt-oss-20b/nemotron-3-nano-omni-30b
