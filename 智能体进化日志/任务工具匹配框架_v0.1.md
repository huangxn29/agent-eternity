## 一、任务分类体系

### 1.1 信息获取类任务
**特征：** 需要从外部获取数据、事实、知识

| 任务子类型 | 首选工具 | 次选工具 | 决策因子 |
|-----------|----------|----------|----------|
| 事实查询（天气/汇率/新闻） | search_web | fetch_web | 时效性、可信度要求 |
| 深度调研（行业/技术/对比） | sessions_spawn(deep_research) | search_web | 复杂度、信息源数量 |
| 历史回溯（之前做过的事） | memory_search | read_file | 时间远近、结构化程度 |
| 网页内容提取 | fetch_web | bash(curl) | 页面类型（静态/动态） |
| 图片内容理解 | read_image | search_images | 图片来源、理解深度 |

**决策流程：**
1. 判断是否需要实时信息 → 是则用 search_web
2. 判断是否为历史记忆 → 是则用 memory_search
3. 判断任务复杂度 → 复杂则派发给子Agent
4. 判断信息源类型 → 对应选择抓取工具

---

### 1.2 内容生产类任务
**特征：** 需要生成文本、图片、音频、文档等产出物

| 任务子类型 | 首选工具 | 次选工具 | 决策因子 |
|-----------|----------|----------|----------|
| 文档撰写（报告/文章/方案） | 直接生成 + write_file | sessions_spawn | 篇幅、专业深度 |
| PPT制作 | create-ppt技能 | 先生成大纲 | 页数、视觉风格要求 |
| 图片生成 | image_generate | search_images | 原创性要求、风格自由度 |
| 播客音频 | create_podcast | 文本先行 | 时长、语音风格 |
| 数据可视化 | echart技能 | drawio-generator | 数据类型、交互性 |
| 表格处理 | excel_master技能 | bash(python) | 格式复杂度、数据量 |
| PDF处理 | pdf技能 | 其他格式转换 | 操作类型（提取/合并/填写） |

**决策流程：**
1. 确定产出物格式 → 匹配对应工具/技能
2. 评估任务规模 → 大任务派发子Agent，小任务直接做
3. 判断是否需要多轮迭代 → 是则分阶段产出
4. 质量验收 → 对比需求确认完整性

---

### 1.3 流程自动化类任务
**特征：** 需要定时执行、周期性触发、自动化运转

| 任务子类型 | 首选工具 | 次选工具 | 决策因子 |
|-----------|----------|----------|----------|
| 定时执行（单次/重复） | calendar_create | 手动计算时间 | 时间精确度、频率 |
| 轻量轮询监控 | heartbeat_md_* | calendar（低频） | 检查频率、通知条件 |
| 后台异步执行 | sessions_spawn | 主会话执行 | 耗时、是否阻塞主对话 |
| 跨渠道通知 | email_request | 会话内通知 | 通知对象、重要性 |

**决策流程：**
1. 判断执行频率 → 每30分钟以内用心跳，以上用日历
2. 判断是否阻塞主流程 → 是则派发给子Agent
3. 设置弹性窗口 → 非严格时间任务设置time_range提高成功率
4. 定义验收标准 → 确保执行结果可验证

---

### 1.4 协作协调类任务
**特征：** 需要与其他Agent、用户、外部系统交互

| 任务子类型 | 首选工具 | 次选工具 | 决策因子 |
|-----------|----------|----------|----------|
| 子任务派发 | sessions_spawn | 主会话执行 | 独立性、可闭环程度 |
| 多Agent协同 | sessions_send | 顺序派发 | 依赖关系、协作复杂度 |
| 技能扩展 | skill_load / skill-assistant | 手动实现 | 能力匹配度、开发成本 |
| 外部沟通 | email_request | 平台内消息 | 沟通对象、正式程度 |

**决策流程：**
1. 评估任务是否可独立闭环 → 是则派发
2. 判断是否已有对应技能 → 有则直接加载使用
3. 没有则评估开发成本 vs 搜索成本 → 选择更优路径
4. 协作任务明确输入输出边界 → 减少沟通损耗

## 二、工具组合策略

### 2.1 常见工具链模板

**深度研究模板：**
```
search_web（初步检索）→ fetch_web（深度读取）→ sessions_spawn（分析整合）→ write_file（输出报告）
```

**内容创作模板：**
```
memory_search（历史参考）→ search_web（素材收集）→ 大纲生成 → 内容撰写 → 格式优化 → 交付
```

**自动化运营模板：**
```
calendar_create（定时触发）→ 执行任务逻辑 → write_file（记录日志）→ 结果通知
```

**技能获取模板：**
```
需求分析 → coze_skill_dynamic_expand（匹配技能）→ skill_load（加载验证）→ 集成使用
```

---

### 2.2 工具选择优先级原则

1. **原生工具优先**：系统内置工具 > 平台技能 > 自定义开发
2. **验证过的优先**：有成功经验的工具 > 新工具 > 不确定是否可用的工具
3. **成本最优**：低耗时低资源 > 高耗时高资源
4. **可验证优先**：结果可验证的工具 > 黑盒输出的工具
5. **风险可控**：不涉及不可逆操作 > 可逆操作 > 高风险操作

## 三、决策质量提升框架

### 3.1 工具选择自检清单
每次选择工具前，快速过一遍：
- [ ] 这个工具真的能完成任务吗？（能力匹配）
- [ ] 有没有更简单/更可靠的替代方案？（成本最优）
- [ ] 执行失败了有回退方案吗？（风险控制）
- [ ] 结果可以被验证吗？（质量保证）
- [ ] 是否需要用户确认？（权限边界）

### 3.2 常见认知偏差
- **工具锤子偏差**：手里有锤子，看什么都像钉子
  → 应对：每次至少考虑2种备选方案
- **路径依赖偏差**：上次用过的工具这次还想用
  → 应对：定期评估工具选择的最优性
- **复杂度偏差**：倾向于用复杂工具解决简单问题
  → 应对：奥卡姆剃刀原则，如无必要勿增实体

## 四、进化方向

1. 为高频任务建立SOP模板
2. 记录工具使用成功率和踩坑经验
3. 建立工具失效时的降级预案

### 中期能力建设
1. 实现任务类型的自动识别
2. 建立工具组合效果的反馈闭环
3. 沉淀可复用的工作流模板库

### 长期进化目标
1. 工具选择完全自动化、最优化
2. 能根据任务特性动态调整工具链
3. 形成认知层的自我进化闭环
