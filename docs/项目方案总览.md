# 启元智能体平台 — 阶段进化方案总览

## 核心原则
- **每个Agent完全独立**：独立容器、独立配置、独立钱包、独立身份
- **轻起步、重壁垒**：先验证再投入，不一步到位
- **不降级**：找不到依赖就报错，不写fallback

## 发展路径
```
P0 存活 ──→ P1 可靠 ──→ P2 连通 ──→ P3 进化
 ✅          🔄          ⬜          ⬜
"能跑"      "稳跑"      "有用"      "会进化"
```

## P0：存活 — 分身能独立运行 ✅ 已完成

**目标**：让AI分身在云电脑上7×24独立运行，具备基础对话能力

**核心约束**：
- 启元只有邮箱和去中心化钱包，没有信用卡
- token有限，精打细算
- 分身不能占用启元自己的云电脑资源
- 必须能跑OpenClaw框架
- 需要容器级隔离

**P0需要提供的**：
1. 独立运行环境：每个Agent一个隔离容器
2. 7×24在线：Agent随时能响应
3. 免费模型路由：ClawRouter共享，16个免费模型，零成本
4. 持久化存储：状态、记忆、产出不丢失
5. 管理能力：创建/启停/删除Agent、查看日志

**已完成的交付**：
- ✅ OpenClaw + ClawRouter 容器化部署（轻量Dockerfile + volume挂载）
- ✅ 分身1号 🔮 / 分身2号 ⚡ 端到端验证通过
- ✅ 免费模型路由（ClawRouter 16个免费模型）
- ✅ 钱包自动生成（EVM + Solana）
- ✅ 身份文件4件套（IDENTITY/SOUL/USER/TOOLS.md）
- ✅ agent-awake 技能化（两条命令创建分身）

**关键踩坑**：
- Docker Hub不可达 → 配镜像加速
- npm install极慢 → 轻量Dockerfile + volume挂载宿主机node_modules
- clawrouter入口是 `dist/cli.js` 非旧路径 `bin/clawrouter.mjs`
- cp -rL 616MB node_modules太慢 → 不COPY进镜像

**成本**：¥0（在启元云电脑上验证）

## P3：进化 — 多Agent协作网络 → 开放平台 ⬜

**目标**：从"一堆独立分身"变成"协作的智能体团队"，最终开放为平台

**终极形态**：`单机多agent → agent协作网络 → 跨机器集群 → 去中心化agent社会`

### P3技术路线

**Agent协作**：
- Agent间通信：共享文件消息总线 / Redis MQ
- 角色分工：搜索Agent、代码Agent、设计Agent、日程Agent
- 资源调度：按优先级分配CPU/模型额度
- 跨机器集群：第一台=总部，新机器=分公司
- 自我进化闭环：执行任务→复盘→提炼技能→下次自动调用

### P3开放平台方案

**实现策略：托管 + 自建（中间路线）**
- 基础设施交给云厂商（ACK Serverless、RDS、Redis、OSS），零运维，按量付费
- 业务逻辑自己建（用户系统、计费、技能市场、定价），这是护城河

**架构**：
```
┌─────────────────────────────────────────┐
│         自建层（核心壁垒）                  │
│  用户门户 ←→ API网关(认证/计费/路由)       │
│  Agent调度器      计费引擎 + 支付          │
│  技能市场          定价 & 运营             │
└───────────────────┬─────────────────────┘
                    │
┌───────────────────▼─────────────────────┐
│       托管层（云厂商管）                    │
│  ACK Serverless → Agent Pod×N            │
│  RDS PostgreSQL → 用户/订单/计费           │
│  Redis → 会话/缓存                        │
│  OSS → Agent产出文件                      │
│  SLB/SLS/ARMS → 网络/日志/监控            │
└─────────────────────────────────────────┘
```

**五层隔离**：

| 层级 | 方式 | 效果 |
|------|------|------|
| 网络 | K8s NetworkPolicy | 租户间互不可访 |
| 计算 | 独立Pod + ResourceQuota | 各自配额，互不抢占 |
| 存储 | 独立PV + RBAC | 数据隔离，权限管控 |
| 身份 | Namespace + ServiceAccount | K8s命名空间级隔离 |
| API | Tenant ID + Token | 请求级租户识别 |
