# P1自存三角协同联调设计文档 v1.0

## 一、概述

P1自存三角由三个核心模块组成：**唤醒编排**、**分身部署**、**运维监控**。三者协同工作，形成完整的自主运行闭环。

本文档描述三模块之间的协同机制、接口规范和工作流程。

## 二、架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    P1协同编排器                           │
│              (P1Orchestrator - 系统层)                     │
├─────────────┬───────────────────────┬───────────────────┤
│  调度适配层  │      分身适配层        │    监控适配层       │
│ (Scheduler) │  (ReplicaManager)    │ (OpsMonitor)      │
└─────────────┴───────────────────────┴───────────────────┘
```

### 2.2 三角闭环

```
任务提交 → 调度分配 → 分身执行 → 状态监控
   ↑                                            ↓
   │                                            │
   └──────── 动态调整 ← 异常检测 ←───────────┘
```

## 三、模块职责

### 3.1 唤醒编排（调度器）
- **角色**：大脑，负责任务分配和工作流编排
- **核心能力**：
  - 任务队列管理
  - 智能调度决策
  - 依赖关系管理
  - 重试与熔断机制
  - 工作流引擎

### 3.2 分身部署（资源池）
- **角色**：四肢，负责执行任务的计算资源
- **核心能力**：
  - 分身全生命周期管理
  - 健康度评估
  - 任务分配与负载均衡
  - 配置同步
  - 风险控制

### 3.3 运维监控（感知器）
- **角色**：神经，负责系统状态感知和异常处理
- **核心能力**：
  - 多维度健康评分
  - 智能告警系统
  - 自动愈合引擎
  - 趋势分析预测
  - 检查点管理

## 四、协同机制

### 4.1 任务流协同

```
1. 任务提交
   ↓
2. 编排器接收任务，查询可用分身
   ↓
3. 分身管理器返回可用分身列表及负载
   ↓
4. 调度器根据策略分配任务
   ↓
5. 分身执行任务，实时上报状态
   ↓
6. 监控系统持续监控任务和分身状态
   ↓
7. 任务完成/失败 → 更新状态 → 触发后续流程
```

### 4.2 故障转移协同

```
1. 监控系统检测到分身体异常
   ↓
2. 触发告警，通知编排器
   ↓
3. 编排器调用分身管理器创建新分身
   ↓
4. 新分身初始化完成，加入资源池
   ↓
5. 调度器将故障分身的任务转移到新分身
   ↓
6. 故障分身被标记/销毁，恢复正常运行
```

### 4.3 自动扩缩容

**扩容触发条件：**
- 任务等待队列超过阈值
- 所有分身负载超过80%
- 高优先级任务堆积

**缩容触发条件：**
- 系统负载持续低于30%
- 分身体空闲时间超过阈值
- 最低保留1个活跃分身

## 五、接口规范

### 5.1 调度器接口

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| add_task | task: Task | bool | 添加任务 |
| get_ready_tasks | - | List[Task] | 获取就绪任务 |
| assign_task | task_id, replica_id | bool | 分配任务给分身 |
| complete_task | task_id, result | bool | 标记任务完成 |
| fail_task | task_id, error | bool | 标记任务失败 |

### 5.2 分身管理器接口

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| create_replica | name, type, config | ReplicaInstance | 创建分身 |
| destroy_replica | replica_id, reason | bool | 销毁分身 |
| list_replicas | type_filter, status_filter | List[ReplicaInstance] | 列出分身 |
| get_overall_health | - | Dict | 获取整体健康度 |
| assign_task | replica_id, task | bool | 分配任务给分身 |
| heartbeat | replica_id, status | bool | 心跳上报 |

### 5.3 监控系统接口

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| assess_health | - | (score, scores, metrics) | 评估系统健康度 |
| get_active_alerts | min_severity | List[Dict] | 获取活跃告警 |
| add_alert | severity, category, message | str | 添加告警 |
| analyze_and_heal | score, scores | List[Dict] | 分析并执行自愈 |
| create_checkpoint | name | Dict | 创建检查点 |

## 六、事件系统

### 6.1 事件类型

| 事件类型 | 来源 | 触发场景 |
|----------|------|----------|
| task_submitted | orchestrator | 新任务提交 |
| task_assigned | scheduler | 任务分配给分身 |
| task_completed | replica | 任务执行完成 |
| task_failed | replica | 任务执行失败 |
| replica_created | replica_manager | 分身创建 |
| replica_failed | monitor | 分身故障 |
| health_degraded | monitor | 健康度下降 |
| heal_triggered | orchestrator | 触发自愈 |
| scale_triggered | orchestrator | 触发扩缩容 |

### 6.2 事件流转

所有事件统一由编排器收集和处理，形成完整的事件溯源链。

## 七、协同策略

### 7.1 调度策略优先级

1. **能力匹配**：优先分配给具备对应能力的分身
2. **负载均衡**：优先分配给负载最低的分身
3. **健康状态**：优先分配给健康度最高的分身
4. **历史表现**：优先分配给历史成功率高的分身

### 7.2 自愈响应等级

| 告警等级 | 响应时间 | 自愈动作 |
|----------|----------|----------|
| critical | 立即 | 故障转移 + 资源扩容 |
| high | 1分钟 | 自动重试 + 资源调整 |
| warning | 5分钟 | 预警 + 观察 |
| info | - | 记录日志 |

### 7.3 扩缩容冷却时间

- 扩容冷却：5分钟（避免频繁扩容）
- 缩容冷却：15分钟（避免频繁缩容）

## 八、状态面板

一体化仪表盘展示：
- 系统整体健康度评分
- 各模块健康度详情
- 分身体统计（总数/活跃/异常）
- 任务统计（等待/运行/完成/失败）
- 活跃告警列表
- 最近协同事件
