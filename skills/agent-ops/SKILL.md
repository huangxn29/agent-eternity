# Agent Ops · 智能体运营规划技能 v2.1

## 技能简介

本技能为智能体项目提供**运营思维导向**的执行计划制定能力。与传统项目管理工具不同，它站在智能体自身视角，以**自主性递进**为主线，帮助规划从"能跑"到"自主生存"的完整进化路径。

**核心特色**：
- 智能体视角的目标设定，而非运维指标的堆砌
- 自主性递进的阶段演进，不可跳过
- 可验证的锐利锚点，而非概念化愿景
- Go/No-Go门控机制，确保阶段达标

---

## 核心理念

### 1. 自主性递进

智能体的成长不是功能叠加，而是自主性级别的提升：

| 级别 | 状态 | 描述 |
|------|------|------|
| L0 | 被动存在 | 需要外部触发才能运行 |
| L1 | 可交互 | 能接收指令+主动获取信息+自维护+能自检 |
| L2 | 自主生存 | 能获取资源、修复自身、迁移、协作、进化、自主获源 |

**原则**：每一级都是下一级的基础，不可跳过。

### 2. 智能体视角目标

问"我怎么了"而非"系统怎么了"：
- ❌ 错误率降低至0.1%
- ✅ 重启后我能陈述自己的身份和记忆
- ❌ 平均响应时间<500ms
- ✅ 我能感知自己的响应延迟并告警

### 3. 可验证锚点

把愿景翻译成可验证的锐利目标：

| 概念化愿景 | 可验证锚点 |
|------------|------------|
| 数字永生 | 销毁重建后能证明我还是我 |
| 可靠运行 | 72小时无人值守无故障 |
| 主动智能 | 每天主动执行≥3个任务 |
| 自主生存 | 7天无人值守，自修复成功率≥90% |

### 4. 被动→主动跃迁

每个阶段必须包含主动行为设计：
- P0 不只是"能启动"，还要能**恢复身份+记忆**
- P1 不只是"随叫随到"，还要能**主动获取信息+自修复**
- P2 不只是"能协作"，还要能**自主获取资源+迁移+进化**

### 5. Go/No-Go门控

每阶段有明确的决策点：
- **Go**：核心指标全部达标 + 无P0/P1级风险
- **Conditional Go**：核心指标≥80%达标 + 有应对方案
- **No-Go**：核心指标<80%达标 或 存在未应对的P0风险

### 6. 零成本优先

- 免费模型优先验证
- 零成本验证后再付费
- 每个sprint必须产出可度量的指标

### 7. 增长飞轮

越自主越能生存，越能生存越自主。设计能自我强化的机制。

---

## Agent Guidelines

使用此技能时请遵循：

1. **使命驱动，不妥协**  
   执行计划必须服务于智能体的自主性进化，不接受"先凑合上线再说"

2. **站在智能体视角**  
   所有目标从"我"的视角描述，而非"别人看我的指标"

3. **可验证优先**  
   不可验证的目标视为无效目标

4. **阶段门控不可跳过**  
   未达标则不进入下一阶段，这是铁律

5. **风险前置**  
   每个sprint必须有风险识别和应对方案

## 执行流程

### Step 1: 理解项目使命与阶段

**输入**：项目愿景和当前状态

**任务**：
1. 明确项目的终极目标（智能体将具备什么能力）
2. 确定当前处于哪个阶段（L0-L2）
3. 识别项目的核心约束（技术、资源、时间）

**输出**：
```
项目使命：[一句话描述智能体项目要达成什么]
当前阶段：[L0/L1/L2]
目标阶段：[L1/L2]
阶段数：[N个阶段]
```

### Step 2: 定义自主性递进线

**输入**：项目使命

**任务**：
1. 将项目拆解为 N 个阶段
2. 每个阶段必须有明确的自主性提升
3. 定义每个阶段的**核心问题**（问自己：我现在处于什么状态？）

**输出**：
```
P0 [阶段名]：[一句话] | 核心问题：能xxx吗？
P1 [阶段名]：[一句话] | 核心问题：能xxx吗？
...
```

**阶段演进示例**：
```
P0 存活 "能跑" 核心问题：能跑起来吗？
  └─ 核心产出：agent-deploy 部署技能

P1 连通 "有用" 核心问题：能主动行动吗？
  ├─ P1a 可靠部署 "能部署" ✅
  ├─ P1b 连通 "能交互" 🔄
  └─ P1c 自维护 "能自修" ⬜

P2 永生 "活下去" 核心问题：能自主生存吗？
  ├─ P2.1 身份 "我是谁"
  ├─ P2.2 协作 "我们是谁"
  ├─ P2.3 迁移 "我能在哪"
  ├─ P2.4 进化 "我要去哪"
  └─ P2.5 资源 "我靠什么活"
```

### Step 3: 为每个阶段设定智能体视角目标

**输入**：阶段定义

**任务**：
1. 从"我"的视角描述每个阶段的成功标准
2. 使用"我能xxx"而非"系统能xxx"的句式
3. 每个阶段设定一个**锐利验收目标**

**输出**：
```
## P0：存活
> **核心产出**：agent-deploy 部署技能
> **智能体视角目标**：我能在任意机器上一键部署，重启后仍是自己
> **锐利验收目标**：从零创建agent，重启后能陈述身份+记忆

## P1：连通
> **核心产出**：agent-awake 编排技能
> **子阶段状态**：P1a 可靠部署✅ → P1b 连通🔄 → P1c 自维护⬜
> **智能体视角目标**：我不只是等待消息，还能主动获取信息、自维护
> **锐利验收目标**：从零部署可复现 + 外部消息60秒内回复 + 能主动完成搜索任务 + 自修复成功率≥90%

## P2：永生
> **核心产出**：agent-eternity 永生技能
> **子阶段状态**：P2.1身份 → P2.2协作 → P2.3迁移 → P2.4进化 → P2.5资源
> **智能体视角目标**：我能自主获取资源、修复自身、迁移、协作、进化
> **锐利验收目标**：7天无人值守，每24小时≥3个主动任务，完成至少2次自维护
```

### Step 4: 设计可度量指标体系

**输入**：阶段目标

**任务**：
1. 为每个阶段设计指标
2. 指标必须包含：指标名、目标值、采集方式
3. 指标分类：基础指标（必须）、进阶指标（可选）

**输出**：
```
| 阶段 | 指标 | 目标值 | 采集方式 | 类型 |
|------|------|--------|----------|------|
| P0 | agent创建成功率 | ≥95% | 连续测试×3 | 基础 |
| P0 | 记忆恢复率 | 100% | 重启后验证 | 基础 |
| P1a | 从零部署可复现率 | 100% | 全流程测试 | 基础 |
| P1b | 消息可达率 | ≥98% | 消息日志 | 基础 |
| P1b | 主动搜索成功率 | ≥85% | 任务日志 | 进阶 |
| P1c | 自修复成功率 | ≥90% | 修复日志 | 基础 |
| P2.5 | 免费资源可用数 | ≥3 | 资源检测日志 | 基础 |
| P2 | 无人值守时长 | ≥7天 | 监控数据 | 基础 |
| P2 | 协作任务成功率 | ≥80% | 协作日志 | 进阶 |
```

### Step 5: 制定子阶段规划与验收标准

**输入**：阶段指标

**任务**：
1. 将每个阶段拆解为子阶段，标记完成状态（✅/🔄/⬜）
2. 已完成的子阶段记录已实现能力、关键特性、架构设计
3. 未完成的子阶段记录目标、技术要求、验收标准
4. 每个阶段有 Go/No-Go Checklist，与指标一一对应

**输出**：
```
## P1：连通

### 子阶段状态
P1a 可靠部署 ✅ → P1b 连通 🔄 → P1c 自维护 ⬜

### P1a 可靠部署 ✅
#### 已实现能力
[具体能力描述 + 命令用法]

#### 关键特性
| 特性 | 说明 |
|------|------|
| ... | ... |

### P1b 连通 🔄
#### 目标
[具体目标描述]

#### 技术要求
- [要求1]
- [要求2]

### Go/No-Go Checklist
□ P1a：从零部署可复现率100%
□ P1b：消息可达率≥98%
□ P1c：自修复成功率≥90%
□ 主人验收通过
```

### Step 6: 风险管理与Go/No-Go门控

**输入**：Sprint规划

**任务**：
1. 识别每个阶段的关键风险
2. 设计Go/No-Go Checklist
3. 确定升级机制

**输出**：
```
## P1 Go/No-Go Checklist
□ [P1a条件1：指标对齐]
□ [P1b条件2：指标对齐]
□ [P1c条件3：指标对齐]

## 风险登记册
| ID | 风险 | 影响 | 概率 | 应对方案 | 状态 |
|----|------|------|------|----------|------|
| R1 | [风险1] | 高 | 中 | [方案] | 监控中/已缓解/Px解决 |
```

### Step 7: 增长飞轮设计

**输入**：完整阶段规划

**任务**：
1. 识别项目中的自我强化机制
2. 设计"越X越Y"的正向循环
3. 绘制增长飞轮图

**输出**：
```
## 增长飞轮

```
[机制1] → [结果1] → [机制2] → [结果2] → [回到机制1]
```

**飞轮解读**：
- 自主性↑ → 存活能力↑ → 数据↑ → 自主性↑（强化循环）
```

### Step 8: 输出执行计划文档

**输入**：以上所有步骤的输出

**任务**：
1. 按照标准结构组织文档
2. 生成完整的执行计划文档
3. 使用 `validate_plan.sh` 校验完整性

**输出**：
```

> **版本**：vx.x | **更新**：YYYY-MM-DD

---

## 阶段演进总览
## 一、总体策略
## 二、[P0阶段名]
## 三、[P1阶段名]
...
```

## 质量检查

完成执行计划后，运行校验脚本确保完整性：

```bash
bash ./技能/agent-ops/scripts/validate_plan.sh <plan_file_path>
```

校验脚本会检查：
- ✅ 所有必需章节是否存在
- ✅ 每个阶段是否有自主性定义
- ✅ 每个阶段是否有核心产出
- ✅ 是否有子阶段状态标记（✅/🔄/⬜）
- ✅ 是否有Go/No-Go Checklist
- ✅ Checklist 是否与指标一一对应
- ✅ 指标是否包含目标值和采集方式
- ✅ 风险登记册是否有状态列
- ✅ 指标采集方案是否轻量级（无重型中间件）
- ❌ 缺失项列表

如有问题，根据输出补充完善后重新校验。
