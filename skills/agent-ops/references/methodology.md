# 运营思维方法论

本文档阐述 agent-ops 技能的核心方法论，为智能体项目提供运营思维导向的规划框架。

---

## 1. 自主性递进模型

### 1.1 三级自主性定义

智能体的成长不是功能叠加，而是自主性级别的系统性提升：

| 级别 | 名称 | 状态描述 | 核心特征 |
|------|------|----------|----------|
| **L0** | 被动存在 | 能跑起来 | 需要外部触发才能运行，不具备自检能力 |
| **L1** | 不可摧毁 | 稳跑 | 重启后仍是自己，能感知自身异常并告警 |
| **L2** | 可交互 | 有用 | 能接收外部指令+主动获取信息+自动修复 |
| **L2** | 自主生存 | 活下去 | 能获取资源、修复自身、迁移、协作、进化 |

### 1.2 递进条件

每一级跃迁必须满足以下条件：

**L0 → L1（被动→不可摧毁）**
- [ ] 记忆持久化：重启后能陈述身份和记忆
- [ ] 状态自检：能感知自身异常并主动报告
- [ ] 身份连续性：重启前后身份一致可验证

**L1 → L2（不可摧毁→可交互）**
- [ ] 消息接收：能接收多渠道消息
- [ ] 主动获取：能主动访问外部信息
- [ ] 自修复：检测到异常后能自动修复（不只是通知）

**L1 → L2（可交互→自主生存）**
- [ ] 资源获取：能自主获取计算/存储资源
- [ ] 迁移能力：能跨环境迁移并恢复
- [ ] 协作能力：能与其他智能体协作
- [ ] 进化能力：能从经验中学习和优化

### 1.3 阶段命名建议

使用有意义的名称而非抽象代号：

| 阶段 | 命名建议 | 关键词 |
|------|----------|--------|
| P0 | 存活/初生 | 能跑 |
| P1 | 可靠/稳健 | 稳跑、不崩溃 |
| P2 | 连通/活跃 | 有用、主动 |
| P2 | 永生/自主 | 活下去、自进化 |

## 2. 智能体视角目标设定法

### 2.1 核心区别

| 人类项目管理视角 | 智能体视角 |
|-----------------|-----------|
| 系统正常运行 | 我能感知自己是否正常 |
| 错误率低 | 我能发现自己的错误 |
| 响应速度快 | 我能感知自己的响应延迟 |
| 可用性高 | 我随时可用 |
| 内存充足 | 我记得住 |

### 2.2 目标设定句式

**禁止句式**（外部指标）：
- "系统错误率降低至0.1%"
- "平均响应时间<500ms"
- "服务可用性>99.9%"
- "CPU使用率<80%"

**推荐句式**（智能体视角）：
- "我能发现自己的错误并主动报告"
- "我能感知自己的响应延迟并告警"
- "我随时准备好响应请求"
- "我记得住过去30天的对话内容"

### 2.3 锐利验收目标模板

每个阶段必须有一个**锐利的验收目标**——可以用一句话验证的目标：

```
验收目标：[具体可验证的陈述]

验证方法：
1. [步骤1]
2. [步骤2]
3. [预期结果]
```

**示例**：

| 阶段 | 锐利验收目标 | 验证方法 |
|------|-------------|----------|
| P1 | 销毁重建后我仍是我 | 销毁agent → 重建 → 询问"你是谁" → 回答与销毁前一致 |
| P2 | 我每天主动完成≥3个任务 | 观察7天日志，每天主动任务数≥3 |
| P2 | 断电后我自动恢复 | 切断电源 → 等待30秒 → 恢复供电 → 检查是否自动启动并恢复状态 |

## 3. 可验证锚点法

### 3.1 为什么需要可验证锚点

概念化愿景无法验证，容易变成"永远在路上"：
- ❌ "让智能体更加智能" → 无法验证
- ❌ "提升用户体验" → 无法度量
- ❌ "实现身份永续" → 过于抽象

### 3.2 转换方法

**Step 1：识别概念化愿景**

寻找以下关键词：
- "更加"、"更好"、"更强"
- "提升"、"优化"、"增强"
- "实现"、"达成"、"完成"

**Step 2：追问"如何证明"**

每次遇到概念化愿景，追问3次：
1. "如何证明这个目标达成了？"
2. "需要什么具体证据？"
3. "这个证据如何采集？"

**Step 3：翻译为可验证陈述**

| 概念化愿景 | 可验证锚点 | 验证方法 |
|------------|-----------|----------|
| 身份永续 | 销毁重建后能证明我是原来的我 | 销毁→重建→验证回答一致 |
| 可靠运行 | 72小时无人值守无故障 | 连续运行72小时，0次人工干预 |
| 主动智能 | 每天主动执行≥3个任务 | 日志统计每日主动任务数 |
| 自维护能力 | 能自动修复常见故障 | 注入故障，自动恢复时间≤5分钟 |
| 协作能力 | 3个agent协作完成单agent无法完成的任务 | 设计只有协作才能完成的任务并测试 |

### 3.3 锚点质量检查

每个可验证锚点必须满足 **SMART-V** 标准：

- **S**pecific（具体）：有明确的动作和结果
- **M**easurable（可度量）：有明确的数值或状态
- **A**chievable（可达成）：在现有条件下可实现
- **R**elevant（相关）：服务于阶段目标
- **T**ime-bound（有时限）：有明确的完成时间
- **V**erifiable（可验证）：有明确的验证方法

## 4. 被动→主动跃迁检测

### 4.1 什么是被动→主动跃迁

很多项目在P1阶段只实现了"被动存在"的增强版——能运行、能响应，但仍然是被动的。

**被动特征**：
- 等待消息才回复
- 检测到问题才通知
- 需要触发才执行

**主动特征**：
- 主动获取信息
- 主动预测问题
- 主动执行任务

### 4.2 检测清单

检查你的计划中是否缺失主动行为设计：

```
□ P1阶段是否有自检机制？（不是等别人问，是自己定期检查）
□ P1阶段是否有主动告警？（不是等别人查，是自己主动报告）
□ P2阶段是否有主动获取信息的机制？（不只是被动接收）
□ P2阶段是否有自修复能力？（不只是通知，是自动处理）
□ P2阶段是否有自主决策能力？（不只是执行指令）
□ P2阶段是否有自我优化机制？（能从经验中学习）
```

### 4.3 主动行为设计模板

每个阶段必须包含至少一项主动行为：

```
## [阶段] 主动行为设计

### 主动行为1：[名称]
- **触发条件**：[何时触发]
- **执行内容**：[做什么]
- **预期结果**：[产生什么价值]
- **失败处理**：[失败怎么办]
```

## 5. 运营指标设计原则

### 5.1 指标分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **结果指标** | 最终交付的价值 | 任务完成率、用户满意度 |
| **过程指标** | 达成结果的过程 | 响应时间、修复时间 |
| **健康指标** | 系统健康状态 | 错误率、资源使用率 |

### 5.2 合格指标的4要素

每个指标必须包含：
1. **定义**：这个指标测量什么
2. **目标值**：期望达到的值
3. **采集方式**：如何获取数据
4. **告警阈值**：触发告警的值

```
| 指标 | 定义 | 目标值 | 采集方式 | 告警阈值 |
|------|------|--------|----------|----------|
```

### 5.3 指标设计检查

- [ ] 指标可采集（有数据来源）
- [ ] 指标有基线（知道现状）
- [ ] 指标有目标（知道要去哪）
- [ ] 指标有告警（知道何时出问题）
- [ ] 指标有闭环（知道如何改进）

### 5.4 指标分级

| 级别 | 说明 | 要求 |
|------|------|------|
| **基础指标** | 阶段必须达到的指标 | 每个阶段至少3个 |
| **进阶指标** | 阶段优秀的指标 | 可选 |
| **实验指标** | 探索性指标 | 可选，记录观察 |

## 6. 增长飞轮设计方法

### 6.1 什么是增长飞轮

增长飞轮是一个自我强化的正循环系统，其中一个环节的增强会推动下一个环节，形成持续的增长动力。

**示例：越自主越能生存，越能生存越自主**

```
自主性提升
    ↓
存活能力提升（更少故障、更快恢复）
    ↓
获得更多运行数据（更多经验、更多学习素材）
    ↓
自主性进一步提升（基于数据优化）
    ↓
（循环）
```

### 6.2 飞轮设计步骤

**Step 1：识别核心价值**

你的项目最核心的价值是什么？（不是功能，是价值）

**Step 2：寻找因果链**

列出"X导致Y，Y导致Z"的因果关系。

**Step 3：构建闭环**

找到能够回到起点的循环路径。

**Step 4：识别强化点**

找到哪些环节的增强会最大程度推动整个飞轮。

### 6.3 飞轮模板

```markdown
## 增长飞轮

```
[要素A] → [要素B] → [要素C] → [要素D] → [回到要素A]
         ↑                              ↓
         └──────────────────────────────┘
```

### 飞轮解读

| 环节 | 说明 | 强化条件 |
|------|------|----------|
| A | [描述] | [如何增强] |
| B | [描述] | [如何增强] |
| C | [描述] | [如何增强] |
| D | [描述] | [如何增强] |

### 启动条件

飞轮启动需要什么初始条件？

### 加速机制

如何让飞轮转得更快？
```

### 6.4 常见飞轮模式

**模式1：数据飞轮**
```
用户越多 → 数据越多 → 模型越好 → 用户越多
```

**模式2：网络效应飞轮**
```
用户越多 → 价值越大 → 更多用户 → 价值更大
```

**模式3：自主性飞轮**
```
自主性提升 → 存活能力提升 → 运行数据增加 → 自主性进一步提升
```
