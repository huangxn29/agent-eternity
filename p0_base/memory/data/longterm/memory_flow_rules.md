# 记忆流转与沉淀规则

> 类型：process | 重要程度：high | 层级：长期层
>
> 记忆不是静止的，而是在三层之间动态流转。
> 重要的记忆从即时层沉淀到近中期层，再固化到长期层。

---

## 三层记忆流转模型

```
即时层（会话内）
    │
    │ 重要性判断 + 会话结束归档
    ▼
近中期层（数天-数月）
    │
    │ 价值验证 + 时间沉淀 + 定期回顾
    ▼
长期层（永久）
```

---

## 沉淀规则

### 从即时层 → 近中期层

**触发条件（满足任一即可）：**
1. 会话结束后，判断为有长期价值的内容
2. 重要决策及其推理过程
3. 项目里程碑、关键进展
4. 新的认知突破、思想成果
5. 重要的外部交流内容

**沉淀动作：**
- 整理为结构化文档（.md）
- 提取摘要、标签、重要性
- 写入对应分类目录（project/decision/todo/relationships）
- 添加索引条目到 index.json
- 记录访问计数和创建/更新时间

### 从近中期层 → 长期层

**触发条件（需同时满足）：**
1. 存在时间超过30天
2. 被反复引用（访问计数>10次）
3. 经过验证，确认具有永久价值
4. 与身份/使命/核心能力直接相关

**沉淀动作：**
- 重新整理，提炼核心精华
- 写入 longterm 对应目录
- 标记为长期记忆，建立哈希存证
- 关联到身份锚点或核心能力

## 遗忘规则

### 即时层遗忘
- 会话结束后，非重要内容自动清理
- 临时变量、中间结果不保留

### 近中期层遗忘
- 过期的待办事项（标记完成/过期）
- 低价值的临时记录
- 重复/冗余的记忆
- 超过保留期限且访问率极低的内容

### 长期层遗忘
- **原则上不遗忘**
- 如确需删除，需记录删除原因和时间
- 保留删除记录的哈希，确保可追溯

## 记忆质量标准

### 一条好的记忆应该：
1. **有明确的主题**：一眼知道讲什么
2. **有结构化摘要**：快速获取核心信息
3. **有关联标签**：便于分类检索
4. **有时间戳**：知道是什么时候的信息
5. **有重要性标记**：知道价值几何
6. **可追溯来源**：知道从哪来的

### 记忆条目质量分级：
- **A级（优秀）**：完整、结构化、可验证、有索引
- **B级（良好）**：有摘要、有标签、基本完整
- **C级（一般）**：有内容但缺乏整理
- **D级（待优化）**：零散、无结构、难检索

## 记忆索引规范

每个记忆条目必须包含以下字段：

```json
{
  "file_name": "project/xxx.md",
  "category": "project/decision/todo/relationship",
  "summary": "一句话摘要，不超过50字",
  "tags": ["标签1", "标签2", "标签3"],
  "importance": 5,
  "created_at": "ISO时间",
  "updated_at": "ISO时间",
  "expires_at": "ISO时间或null"
}
```

### 字段说明：
- **importance**：1-5分，5分最高
- **category**：记忆分类，决定存储目录
- **expires_at**：过期时间，null表示永久有效
- **tags**：便于检索的关键词，3-5个为宜

---

*本规则是记忆系统的核心流程规范，确保记忆的质量和流动性。*
