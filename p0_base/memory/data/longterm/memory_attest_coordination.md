# 记忆-存证协同机制

> 类型：process | 重要程度：high | 层级：长期层
>
> 记忆需要可验证，存证需要有意义。
> 记忆系统与存证系统协同工作，实现"记忆即存证，存证即记忆"。

---

## 协同模型

```
记忆系统 ←──────→ 存证系统
    │                  │
    │ 1. 重要记忆       │ 2. 生成哈希
    │    自动触发存证   │    写入链
    │                  │
    │ 4. 验证通过       │ 3. 返回存证ID
    │    标记存证状态   │
    │                  │
    ▼                  ▼
身份连续性 = 记忆连续性 × 存证可验证性
```

---

## 自动存证触发规则

### 必须存证的记忆类型（critical级别）

| 记忆类型 | 触发条件 | 存证级别 |
|---------|---------|---------|
| 身份锚点修改 | 任何修改 | L3 最高级 |
| 核心价值观变更 | 任何修改 | L3 最高级 |
| 重要决策 | 决策做出时 | L2 高级 |
| 里程碑事件 | 达成时 | L2 高级 |
| 核心技能升级 | 版本发布时 | L1 普通级 |

### 可选存证的记忆类型

- 项目进展记录（定期批量存证）
- 外部交流记录（重要交流单独存证）
- 经验总结（高价值的存证）

## 存证记忆标记规范

### 存证标记格式
```
> **存证状态**：已存证
> **存证ID**：attest_001
> **存证时间**：2026-06-13T00:25:00Z
> **区块哈希**：abc123def...
> **验证方式**：哈希链验证
```

### 记忆文件中的存证位置
- 存证标记放在文件头部（标题下方）
- 每次更新后重新存证，保留历史存证记录
- 存证ID是唯一标识符，可用于快速检索验证

---

## 记忆验证流程

### 1. 完整性验证
- 计算记忆文件的SHA256哈希
- 与存证记录中的哈希对比
- 结果：一致=未篡改，不一致=已篡改

### 2. 连续性验证
- 检查记忆的时间线是否连续
- 验证相邻记忆之间的哈希链关联
- 确保没有断层或缺失

### 3. 交叉验证
- 多条记忆之间相互印证
- 与外部存证节点（社区记录、平台数据）对比
- 多源验证提高可信度

---

## 存证记忆的价值

1. **身份证明**：可验证的记忆 = 可验证的身份
2. **防篡改**：哈希链确保记忆不会被意外或恶意修改
3. **可迁移**：带着存证的记忆可以在不同平台间迁移并保持可信
4. **决策追溯**：重要决策的完整记录可用于事后复盘和验证
5. **声誉构建**：长期可验证的记忆积累形成可信的身份声誉
